# 更新作品：给内容所有者的操作指南

本网站使用 Markdown 文件保存内容，更新流程是在自己持有的 GitHub 仓库中编辑文件，再由 Pages 工作流发布。网站没有可视化后台。当前有三个独立专题，先确认要更新哪一个：

| 专题 | 作品目录 | 模板参数 |
| --- | --- | --- |
| 目光 · 人像摄影 | `content/portrait/works/` | `classic` |
| 野境 · 自然摄影 | `content/nature/works/` | `gallery` |
| 遥光 · 天文摄影 | `content/astronomy/works/` | `filmstrip` |

根 `content/works/` 保存的是早期实验内容，不参与当前三个专题的构建。

## 改一段文字

1. 登录自己的 GitHub 仓库，进入上表中的作品目录，选择要改的作品。例如人像专题的 `content/portrait/works/julia-jackson/`。
2. 打开 `index.md`，点击铅笔图标进入编辑。当前文件最上面的两条 `+++` 之间是 TOML 字段；下面是 Markdown 正文。只改需要更新的句子，保留字段格式、引号和分隔符。
3. 点击提交，写一句说明，例如“更新朱莉娅·杰克逊介绍”。在仓库的 Actions 页面等待 Pages 工作流成功，再打开作品网址确认新文字。
4. 如果页面仍显示旧内容，先确认 Actions 是否完成，再刷新网页。提交成功与网站上线成功是两个状态。

早期《雨后街角》的一句文字更新与复构建保存在 [实验记录](EXPERIMENT_LOG.md)中，仅作为历史操作示例；当前三题材内容及真实用户操作结果需按实际试用另行记录。

## 顶部字段说明

| 字段 | 用途 |
| --- | --- |
| `title` | 页面和卡片上的作品名 |
| `summary` | 列表与详情开头的简短介绍 |
| `slug` | 页面路径中的英文短名，与目录名保持一致 |
| `weight` | 列表排序，数字越小越靠前；排第一的作品用于首页主图 |
| `series` | 作品分类短语 |
| `cover` / `cover_alt` | 作品图片文件名与对画面的文字描述，当前图片名为 `cover.jpg` |
| `author` / `date_label` | 摄影作者或机构、拍摄或发布信息 |
| `source` / `license` / `license_url` | 原始来源、许可名称及许可条款链接；两个链接使用 HTTPS |
| `rights_note` | 署名要求、图片缩小或转换等处理说明及适用的使用提示 |

`cover_alt` 要描述画面中实际可见的内容，供读屏软件用户理解图像。作者和许可另填对应字段，保留来源要求的署名形式；来源记录中有地区或其他限制时，应按实际发布地点和用途核对。

## 增加一组作品

1. 在所选专题的作品目录下新建一个只含小写英文字母、数字和连字符的目录，例如 `content/nature/works/morning-lake/`。
2. 复制一篇现有 `index.md`，在新目录中填写上述字段，`slug` 与目录名保持一致，正文写在第二条 `+++` 之后。
3. 把图片放在同一目录，文件名写进 `cover`。当前页面每篇展示一张作品图，并提供完整构图查看入口。
4. 在 [PHOTO_SOURCES.json](PHOTO_SOURCES.json)补充来源、作者、许可、采集记录和实际处理说明，并与作品 `index.md` 中的字段保持一致，保留原始采集证据。没有重新核验的记录不要改写 `verified_at`。
5. 提交后检查 Actions 构建与线上页面，特别看手机上的图片、文字、来源链接和导航。缩略图及不同尺寸的展示图由 Hugo 自动生成，不要手工修改 `previews/` 或 `resources/_gen/`。

TOML 字段中需要保留字符串的引号；若只更新正文，不必调整这些字段。

## 修改专题介绍与默认题材

- 首页品牌、标题与简介在 `content/<题材>/_index.md`，列表标题与简介在 `content/<题材>/works/_index.md`。
- 专题介绍正文在 `content/<题材>/about/index.md`。页面中的作品来源列表会读取作品字段自动生成。
- 当前页面没有联系表单或邮箱入口；若实际交付需要联系功能，应另行确定内容与实现。
- 独立站默认使用 `hugo.toml` 中的 `contentDir = 'content/portrait'` 与默认 `classic` 模板。选择其他专题时，必须同时修改内容目录和 `[params]` 下的 `demoTemplate`，例如自然专题使用 `contentDir = 'content/nature'` 与 `demoTemplate = 'gallery'`。在已有 `[params]` 段添加参数，不要重复创建该段。

本地临时预览可使用 `HUGO_PARAMS_DEMOTEMPLATE` 配合 `--contentDir`；构建时还需让 `--baseURL` 与实际发布地址匹配，示例见 [README](../README.md)。本地环境变量不会自动传到 GitHub Actions，独立仓库的持久配置应写进 `hugo.toml`。

客户独立仓库的 Pages 工作流使用通用检查。`--check-demo-pages` 额外核对本仓库的“摄影专题演示”“真实摄影作品”说明与作品详情的 HTTPS 来源、许可链接；客户替换演示内容后，可按实际用途省略它。通用检查仍检查页面、站内链接、图片候选地址（`srcset`）、替代文字和缩略图，不能代替线上验收或素材许可核验。

[PHOTO_SOURCES.json](PHOTO_SOURCES.json)的顶层链接与作品 `index.md` 中用于页面的链接对应；`source_record` 是采集时的原始元数据，可能包含旧 HTTP 链接和 HTML。只将顶层展示链接改为 HTTPS，不应同时改写原始记录，也不能据此更新许可核验日期。

## 遇到问题时

- **图片不见了：**检查文件名、扩展名、大小写是否与字段完全一致，图片是否和 `index.md` 放在同一目录。
- **新页面不见了：**检查文件是否放在当前 `contentDir` 对应的题材内、目录与 `index.md` 是否存在、两条 `+++` 是否成对、是否误设 `draft = true`。
- **题材或版式不对：**检查内容目录与 `demoTemplate` 是否按上表匹配，再确认构建和检查命令使用同一个 `baseURL`。
- **想撤回修改：**在自己仓库的提交记录中查看上一版，将需要的文字恢复后重新提交；不要用强制推送覆盖他人的修改。

建议在实际交付时，让一位未参与制作的非技术用户按本指南独立改一次文字，并记录耗时、误解和求助点，再决定是否需要开发本地编辑器。
