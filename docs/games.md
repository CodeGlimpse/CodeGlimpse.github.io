# 游戏栏目实现与维护

游戏直接运行在博客页面中，当前提供十九款游戏、三十八个中英文游戏页面，目录支持即时搜索与玩法筛选。游戏不使用 iframe，也不提供存档或历史最高分；棋盘、得分、步数和计时仅存在于当前页面内存中，刷新后回到未开始状态。

## 目录搜索

- 每张卡片的检索文本包含中英文标题、说明、标签，以及注册表中两种语言的 `keywords`。可以用“扫雷”“双人”“tetris”等名称、别名或玩法查找。
- 英文字母不区分大小写，全角输入经 NFKC 归一化；连字符、下划线和空白统一处理，多个关键词必须全部匹配。检索使用字面文本，不执行正则或 HTML。
- 中文输入法组合期间暂不更新结果；回车不会提交页面，Escape 和清空按钮恢复全部卡片。结果数量通过状态区域播报，隐藏卡片不会进入键盘焦点顺序。
- 不请求搜索接口、不写入浏览器存储。脚本不可用时保留全部静态卡片；搜索区域沿用 Clarity 屏蔽标记。
- 筛选脚本输出在 `/js/game-catalog.<hash>.js`，不导入游戏控制器。构建和线上检查继续禁止目录加载 `/js/games/` 下的游戏代码，并校验搜索框与本地筛选脚本存在。

## 状态与输入边界

- 游戏代码不读写 localStorage、sessionStorage、IndexedDB 或 cookie；内容检查会拦截这类依赖。博客原有的主题和隐私设置仍由其已有代码管理。
- 全部游戏提供暂停和重开按钮，按键只在游戏区域内生效。方向类棋盘用空格暂停；方块堆叠用空格快速落底、反应测试用空格响应信号，这两款采用 P/Esc 暂停。各游戏的完整按键以页面玩法说明为准。点击游戏外部会暂停并释放焦点。
- 扫雷提供翻开/插旗模式、鼠标右键和 F 键；网格使用方向键移动焦点，格子的可操作状态有可访问性标记。四子棋同时用颜色和数字区分玩家；数字滑块点按或滑动后恢复棋盘焦点，避免移动的格子变为空位后丢失键盘输入。
- 手机通过点按、拖动、滑动或专用按钮操作。主要控制按钮至少 44px；扫雷等密集棋盘的目标尺寸在 375px 手机视口下验证不小于 24px，并保持在页面宽度内。
- 切换窗口、隐藏页面和离开页面时暂停；卸载时清理事件和计时器。浏览器保留页面内存返回时可继续暂停状态，刷新始终重置。
- 记忆翻牌的错配延时会在暂停、重开和销毁时清理。贪吃蛇每个 tick 最多接受一次转向；2048 每次移动只合并一次，无效移动不生成新方块。
- 打地鼠按有效运行时间计算截止时刻，同一只只计分一次。打砖块和点按飞行采用有界时间步与细分碰撞计算，暂停或离开页面时取消帧循环，恢复时重新建立时间基准。
- 方块堆叠每袋包含七种不同方块，消行后再生成新方块；手动平移不会重置重力计时。推箱子的撤销历史只属于当前关卡，下一关和重开会清空历史。
- 井字棋的电脑落子计时器在暂停、重开和销毁时取消，继续后重新安排尚未完成的电脑回合。数独从合法终盘删格，每次删格都确认仍有唯一解。
- 反应测试在同一个绘制帧中更新绿色信号并记录起点，以鼠标/触屏的 `pointerdown`、键盘的 `keydown` 事件时间戳结束计时。松开、兼容 click 和键盘连发不会再触发一次；保留无指针事件的虚拟按钮激活。
- 反应测试暂停、重开和销毁时同时取消等待定时器与待绘制信号；时间戳早于信号、但延后送达的输入按抢跑处理。暂停保留已完成样本。记忆序列在演示期间拒绝输入，暂停清理全部闪烁计时器，继续时从头演示当前序列。
- 回合结束后保留最终棋盘，结果显示在状态文字中；重开清除旧计时器、得分、棋盘及输入状态。
- 游戏模块加载失败时显示刷新重试入口，不把失败状态表现为正在游玩。
- 棋盘区域具有 Clarity 屏蔽标记。未增加游戏统计事件；真实供应商 SDK 行为仍属于既有独立核验范围。

- `npm.cmd test`：206/206 单元测试通过，涵盖全部推箱子关卡可解、数独唯一解、电脑合法落子、消行计分、检索规则及反应测试的输入时间戳和抢跑边界。
- `npm.cmd run test:e2e -- --workers 2`：130/130 Chromium 测试通过，其中 67 项覆盖游戏和目录搜索。
- 反应测试时序回归共 8 项：绿色状态后 230ms 按下、保持 80ms 再松开，旧版计为 310ms，修复后为 230ms；同时覆盖空格/回车、触屏抬起、事件排队、虚拟点击、连发和信号帧取消。绘制帧同步减少调度误差，实际屏幕刷新和设备链路仍由运行环境决定。
- 浏览器测试涵盖双语与全角检索、多关键词、IME 输入、空结果、键盘清空、无 JavaScript 目录、页内运行、延迟加载、无 iframe、键盘和触屏、暂停重开、刷新重置及存储被禁止。
- 版本、工作流、89 个 JS 文件、内容、分发脚本和分类对比度检查通过；独立 Hugo 构建为 ZH 77 / EN 76，产物检查通过。Windows 缺少 Bash 解析器，分发脚本的 `bash -n` 由现有 Ubuntu CI 执行。

- 线上巡检随注册表纳入双语游戏目录和三十二个游戏页面，检查搜索脚本及无需执行即可发现的延迟加载模块，共 110 个端点。发布时以 `SITE_SOURCE_COMMIT` 校验对应提交的源标记，部署结果按本节对应提交在 Actions 查询。

1. 在注册表添加 ID、双语标签和两种语言的非空 `keywords`，新增两种语言的 `games/<id>/index.md`，设置一致的 `game_id`。

4. 补充规则边界和实际游玩测试，运行现有检查链，检查两种语言、暗色和手机布局后再发布。
