# 更新作品的操作指南（演示版）

这份指南先验证 Markdown 更新流程。本地可视化编辑器尚未实现。

## 修改现有作品

1. 在客户自己持有的 GitHub 仓库中，打开 `content/works/` 或 `content/projects/`，进入要修改的作品目录，打开 `index.md`。
2. 点击编辑，修改文件顶部的标题、简介、分类或下方正文。保留开头与结尾的 `---`，字段名和冒号不要删掉。
3. 在页面下方填写本次修改说明并提交。等待仓库的 Pages 工作流完成，再打开作品网址检查文字与图片。

## 新增作品

1. 参照现有作品，在 `content/works/` 下新建一个英文短名目录，并在其中创建 `index.md`。项目案例则建在 `content/projects/` 下。
2. 复制同类型作品的 `index.md` 作为起点，填写 `title`（标题）、`summary`（列表简介）、`category`（分类）、`cover`（封面文件名）、`cover_alt`（图片文字说明）和 `weight`（排序）。
3. 把封面与正文图片上传到**同一作品目录**，在 `cover` 中填写准确文件名。正文图片写成 `![图片说明](图片文件名.jpg)`。文件名建议只用小写英文字母、数字和连字符。
4. 提交后查看 Pages 构建结果与线上页面；确认列表封面、详情图片和手机排版正常。

## 常见问题

- **图片不见了：**检查大小写、扩展名和目录是否完全对应。`cover` 只写同目录文件名。
- **网站没更新：**先看仓库 Actions 里的 Pages 工作流是否完成，再刷新公开网址。提交成功与上线成功是两个不同状态。
- **页面没出现：**检查 `index.md` 是否在正确目录、文件顶部的 `---` 是否成对、有没有设置 `draft: true`。
- **误改了内容：**保留仓库提交记录；从此前提交恢复文件后再次提交。不要用强制推送覆盖其他人的修改。

本指南涉及的账号登录、仓库操作和域名配置由客户自己持有和控制。实际交付时，应让客户按本指南独立完成一次更新，并把卡住的步骤记录下来，再决定本地编辑器的优先功能。
