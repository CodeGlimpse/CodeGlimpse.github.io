# 游戏栏目实现与维护

游戏直接运行在博客页面中，当前提供记忆翻牌、贪吃蛇和 2048，每款都有中文和英文页面。游戏不使用 iframe，也不提供存档或历史最高分；棋盘、得分、步数和计时仅存在于当前页面内存中，刷新后回到未开始状态。

## 页面与代码

| 内容 | 位置 |
| --- | --- |
| 游戏注册表 | [data/games.json](../data/games.json) |
| 双语目录和说明 | `content/zh-cn/games/`、`content/en/games/` |
| 列表与游戏页面 | [list.html](../layouts/games/list.html)、[single.html](../layouts/games/single.html) |
| 游戏样式 | [games.css](../assets/css/games.css)，只在游戏页面加载 |
| 延迟加载入口 | [bootstrap.js](../assets/js/games/bootstrap.js) |
| 通用控制 | [ui.js](../assets/js/games/ui.js)，暂停、重开、键盘、滑动、焦点与计时 |
| 单局规则 | `assets/js/games/<id>-core.js`，可通过 Node 单元测试验证 |
| 页面交互 | `assets/js/games/<id>.js`，将规则状态渲染到当前 DOM/Canvas |

访问路径为 `/games/`、`/games/memory/`、`/games/snake/`、`/games/2048/` 及对应的 `/en/` 路径。目录页只加载卡片和样式；游戏页先显示界面，点击“开始游戏”后才导入对应的、带 SHA-256 指纹的本地 JavaScript 模块。

## 状态与输入边界

- 游戏代码不读写 localStorage、sessionStorage、IndexedDB 或 cookie；内容检查会拦截这类依赖。博客原有的主题和隐私设置仍由其已有代码管理。
- 棋盘接收方向键/WASD/空格，按钮和滑动支持手机操作。点击游戏外部会暂停并释放焦点，使页面键盘操作恢复正常。
- 切换窗口、隐藏页面和离开页面时暂停；卸载时清理事件和计时器。浏览器保留页面内存返回时可继续暂停状态，刷新始终重置。
- 记忆翻牌的错配延时会在暂停、重开和销毁时清理。贪吃蛇每个 tick 最多接受一次转向；2048 每次移动只合并一次，无效移动不生成新方块。
- 游戏模块加载失败时显示刷新重试入口，不把失败状态表现为正在游玩。
- 棋盘区域具有 Clarity 屏蔽标记。未增加游戏统计事件；真实供应商 SDK 行为仍属于既有独立核验范围。

## 缓存与体积

本版使用小型指纹 JS/CSS，可沿用现有 Service Worker 对成功同源资源的缓存。缓存的是程序和页面文件，不是玩家的单局状态。未增加全量游戏预取、专属离线包或安装入口。

当前生产构建的模块大小：

| 资源 | 压缩后文件 | 本地 gzip 测量 |
| --- | ---: | ---: |
| 记忆翻牌（含通用控制） | 6,125 B | 2,671 B |
| 贪吃蛇（含通用控制） | 7,066 B | 3,140 B |
| 2048（含通用控制） | 5,948 B | 2,583 B |
| 加载入口 | 1,413 B | 738 B |
| 游戏样式 | 8,743 B | 2,316 B |

gzip 为本地测量，不代表服务器实际传输编码。产物检查将单款游戏 JS 的上限设为 128 KB。未增加 npm 依赖或第三方图片、音频资源；Hugo 同步的 `assets/jsconfig.json` 使用通用相对路径映射。

## 添加下一款小游戏

1. 在注册表添加 ID 和双语标签，新增两种语言的 `games/<id>/index.md`，设置一致的 `game_id`。
2. 新增纯规则模块与页面交互模块，更新游戏页面中的棋盘/指标/控制布局和封面样式；游戏选择器与 CSS 均限制在自己的区域。
3. 页面模块导出 `mount(root)`，返回 `pause()` 和 `destroy()`。沿用通用控制并清理自己的计时器，保持无存档的约束。
4. 补充规则边界和实际游玩测试，运行现有检查链，检查两种语言、暗色和手机布局后再发布。
