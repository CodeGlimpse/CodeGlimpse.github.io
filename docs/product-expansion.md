# 产品扩展基线

CodeGlimpse 的产品扩展保持浏览器本地处理和静态部署边界，不引入账号或服务端工作区。站点目前默认启用 Google Analytics 4、百度统计和 Microsoft Clarity；统计只用于页面与整体交互分析，并受双语隐私说明、显式屏蔽标记和本地退出开关约束。

## 当前能力

- 分享与导出：普通工具可将可编辑输入编码到 URL 片段，所有工具支持本地 JSON 快照下载。
- 敏感保护：JWT 和密码工具不生成或复制 URL 分享链接，仍可导出本地快照。
- 离线使用：Service Worker 缓存已访问页面和静态资源，网络不可用时回退到离线说明页；网站不提供浏览器安装入口。
- 本地预设：`CodeGlimpseWorkspace` 提供最多 20 个命名预设的保存、读取、列出和删除接口，数据只写入当前浏览器的 localStorage。
- 隐私控制：页面披露统计服务和数据边界；工具输入、输出、密码、JWT、分享 Hash 和本地预设不作为统计事件发送。用户可以在隐私说明页关闭后续统计脚本。

## 设计边界

1. 不上传工具输入、分享内容、导出快照或预设数据。
2. 站点统计必须有明确的用户告知、供应商范围和退出路径；不得把工具输入、输出、密码、JWT、分享 Hash 或本地预设作为事件参数发送。
3. 分享链接只适用于用户明确选择的普通工具输入；敏感工具保持禁用。
4. 新能力必须有中英文页面、单元测试、E2E 和线上资源检查。

## 后续演进

- 为预设接口增加按工具隔离的 UI，而不是扩大共享数据格式。
- 在确认离线缓存命中率后，再评估更细的缓存更新策略；如果未来需要安装能力，应重新设计面向博客的 PWA，而不是恢复工具版安装配置。
- 批量处理、多工具工作流和导入导出格式应先定义版本化数据结构，再实现界面。
