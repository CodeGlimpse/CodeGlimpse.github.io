# 更新作品：给内容所有者的操作指南

本网站使用 Markdown 文件保存内容。当前验证的是“在客户自己持有的 GitHub 仓库中编辑文件，再由 Pages 工作流发布”的流程，没有可视化后台。

## 改一段文字

1. 登录自己的 GitHub 仓库，进入 `content/works/`，选择作品目录，例如 `rain-street/`。
2. 打开 `index.md`，点击铅笔图标进入编辑。最上面的两条 `---` 之间是字段；下面是正文。只改需要更新的句子即可。
3. 点击提交，写一句说明，例如“更新雨后街角介绍”。在仓库的 Actions 页面等待 Pages 工作流成功，再打开作品网址确认新文字。
4. 如果页面仍显示旧内容，先确认 Actions 是否完成，再刷新网页。提交成功与网站上线成功是两个状态。

本实验就是按上述思路先构建旧句子，再把《雨后街角》的一句正文改写并重新构建。记录见 [实验记录](EXPERIMENT_LOG.md)。这只是执行者模拟，不等于真实客户独立完成。

## 顶部字段说明

| 字段 | 用途 |
| --- | --- |
| `title` | 页面和卡片上的作品名 |
| `summary` | 列表与详情开头的简短介绍 |
| `slug` | 页面路径中的英文短名，与目录名保持一致 |
| `weight` | 列表排序，数字越小越靠前 |
| `series` | 作品分类短语 |
| `cover` / `cover_alt` | 封面文件名与对图片内容的文字说明 |
| `detail` / `detail_alt` / `detail_caption` | 可选的第二张图、文字说明和图下说明 |

`alt` 要描述画面中实际可见的内容，供读屏软件用户理解图像，也应说明演示图的 AI 来源。更换真实作品后，应填写真实的画面描述，并确认公开发布权。

## 增加一组作品

1. 在 `content/works/` 下新建一个只含小写英文字母、数字和连字符的目录，例如 `morning-room/`。
2. 复制一篇现有 `index.md`，在新目录中填写上述字段，`slug` 与目录名保持一致，正文写在第二条 `---` 之后。
3. 把封面图片放在同一目录，文件名写进 `cover`。如有第二张图，再添加 `detail`、`detail_alt` 和 `detail_caption`；没有第二张图就删去这三个字段。
4. 提交后检查 Actions 构建与线上页面，特别看手机上的图片、文字和导航。缩略图及不同尺寸的展示图由 Hugo 自动生成，不要手工修改 `previews/` 或 `resources/_gen/`。

## 修改简介与联系方式

- 介绍正文在 `content/about/index.md`。
- 演示联系信息在 `hugo.toml` 的 `contactPlaceholder`。当前的 `example.invalid` 地址不可用于收信。
- 正式发布前，还需核对 `hugo.toml` 里的站名、网站说明，以及每张图片和作品文字。不要留下“虚构演示”的客户页面内容。

## 遇到问题时

- **图片不见了：**检查文件名、扩展名、大小写是否与字段完全一致，图片是否和 `index.md` 放在同一目录。
- **新页面不见了：**检查目录与 `index.md` 是否存在、两条 `---` 是否成对、是否误设 `draft: true`。
- **想撤回修改：**在自己仓库的提交记录中查看上一版，将需要的文字恢复后重新提交；不要用强制推送覆盖他人的修改。

建议在实际交付时，让一位未参与制作的非技术用户按本指南独立改一次文字，并记录耗时、误解和求助点，再决定是否需要开发本地编辑器。
